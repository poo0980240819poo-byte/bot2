# Merged Discord Bots (Review + Payment + Status)

บอท 3 ตัวรันรวมกันใน service เดียวบน Railway (ประหยัดทรัพยากร) แต่ยังเป็นแอปบอทคนละตัวใน
Discord Developer Portal — ต้องมี Token/Application ID ของตัวเองคนละชุด

## ขั้นตอนตั้งค่า (ทำตามลำดับ ห้ามข้าม)

### 1. สร้างแอปบอทใน Discord Developer Portal (3 แอป)

ไปที่ https://discord.com/developers/applications แล้วสร้างแอปใหม่ 3 แอป (ถ้ายังไม่มี):
- แอปบอทรีวิว
- แอปบอทโอนเงิน
- แอปบอทสถานะ (ออนไลน์/ออฟไลน์)

สำหรับแต่ละแอป:
1. เมนู **Bot** → กด **Reset Token** → copy token เก็บไว้ (จะเห็นครั้งเดียว)
2. เมนู **OAuth2 → General** → copy **Client ID** เก็บไว้

### 2. สร้าง Invite Link — ต้องติ๊ก scope ให้ครบ

จุดที่พลาดบ่อยที่สุด: ถ้า invite บอทเข้าเซิร์ฟเวอร์โดยติ๊ก scope แค่ `bot`
เดียว **จะ deploy slash command ไม่ได้** (จะเจอ error `20012 not authorized`)

ที่เมนู **OAuth2 → URL Generator** ของแต่ละแอป ต้องติ๊กทั้ง:
- ✅ `bot`
- ✅ `applications.commands`

แล้วเลือก permission ที่ต้องใช้ (เช่น Send Messages, Manage Messages, Attach Files —
บอทสถานะใช้แค่ Send Messages + Embed Links + Use Slash Commands)
copy link แล้วเปิดในเบราว์เซอร์เพื่อเชิญบอทเข้าเซิร์ฟเวอร์ ทำแบบนี้กับทั้ง 3 แอป

### 3. ตั้งค่า Environment Variables บน Railway

ไปที่ Railway → service → tab **Variables** แล้วใส่ให้ครบตามชื่อนี้เป๊ะๆ (ตรงตาม `.env.example`):

| ชื่อตัวแปร | คำอธิบาย |
|---|---|
| `GUILD_ID` | ID เซิร์ฟเวอร์ (ใช้ร่วมกันทั้ง 2 บอท) |
| `REVIEW_DISCORD_TOKEN` | Token ของแอปบอทรีวิว |
| `REVIEW_CLIENT_ID` | Client ID ของแอปบอทรีวิว |
| `REVIEW_CHANNEL_ID` | ห้องที่จะโพสต์รีวิว (ไม่ใส่ก็ได้ — จะโพสต์ในห้องที่ใช้คำสั่งแทน) |
| `PAYMENT_DISCORD_TOKEN` | Token ของแอปบอทโอนเงิน |
| `PAYMENT_CLIENT_ID` | Client ID ของแอปบอทโอนเงิน |
| `SLIP_CHANNEL_ID` | ห้องเก็บสลิปที่รอแอดมินตรวจสอบ |
| `STATUS_DISCORD_TOKEN` | Token ของแอปบอทสถานะ |
| `STATUS_CLIENT_ID` | Client ID ของแอปบอทสถานะ |
| `STATUS_ANNOUNCE_CHANNEL_ID` | ห้องประกาศที่จะโพสต์ "ร้านเปิดรับบริการแล้ว" ตอนกดออนไลน์ |
| `PORT` | ปกติใส่ `8080` (Railway จะ inject ให้เองถ้าไม่ใส่ก็ได้) |

⚠️ **ข้อควรระวังตอน copy token:**
- ห้ามให้มีช่องว่าง/ขึ้นบรรทัดใหม่ติดมาตอนวาง
- ลบค่าเดิมออกให้หมดก่อนวางค่าใหม่ (อย่าวางทับ)
- เช็คให้แน่ใจว่า Token กับ Client ID เป็นของแอปเดียวกัน (ไม่สลับกันระหว่างบอทรีวิว/โอนเงิน)

### 4. Push ขึ้น GitHub แล้วต่อกับ Railway

- Push โปรเจกต์นี้ทั้งหมดขึ้น repo (โครงสร้างไฟล์ต้องตรงตามด้านบน โดยเฉพาะ `bots/` ต้องเป็นโฟลเดอร์จริง)
- ต่อ Railway service เข้ากับ repo นี้ (หรือถ้าใช้ service เดิม ให้ push ทับแล้ว Railway auto-deploy)

### 5. เช็ค log หลัง deploy

ควรเห็นบรรทัดประมาณนี้:
```
✅ [รีวิว] Deploy คำสั่งสำเร็จไปที่เซิร์ฟเวอร์ GUILD_ID=...
✅ [โอนเงิน] Deploy คำสั่งสำเร็จไปที่เซิร์ฟเวอร์ GUILD_ID=...
🤖 [รีวิว] ล็อกอินสำเร็จในชื่อ ...
✅ [โอนเงิน] บอทออนไลน์แล้ว: ...
```

ถ้าบอทตัวไหน token ผิด จะขึ้น warning แล้ว**ข้ามเฉพาะบอทตัวนั้น** (อีกตัวยังรันต่อได้ตามปกติ
ไม่ crash ทั้ง container แบบเวอร์ชันก่อนหน้า)

## คำสั่งที่ใช้ในเซิร์ฟเวอร์

- `/setup-review` — โพสต์แผงเลือกสินค้าเพื่อเขียนรีวิว (ต้องมีสิทธิ์ Manage Server)
- `/โอนเงิน` — เริ่มขั้นตอนชำระเงิน + แนบสลิป
- `/setup-status` — โพสต์แผงปุ่ม 🟢 ออนไลน์ / 🔴 ออฟไลน์ (ต้องมีสิทธิ์ Manage Server)

### บอทสถานะ ทำงานยังไง

1. รันคำสั่ง `/setup-status` ในห้องที่ต้องการให้แผงปุ่มอยู่ (ทำครั้งเดียว)
2. เวลาไม่อยู่ กดปุ่ม **🔴 ออฟไลน์** — ถ้ามีลูกค้าเปิดห้องทิกเก็ตใหม่ (ห้องขึ้นต้น `ticket-`)
   ระหว่างนี้ บอทจะทักในห้องนั้นทันทีว่าแอดมินไม่อยู่ กรุณารอสักครู่
3. พอกลับมา กดปุ่ม **🟢 ออนไลน์** — บอทจะ:
   - โพสต์ประกาศไปที่ห้อง `STATUS_ANNOUNCE_CHANNEL_ID` ว่าร้านเปิดรับบริการแล้ว
   - ไล่ส่งข้อความแจ้งเตือนไปทุกห้องทิกเก็ตที่เปิดมาระหว่างออฟไลน์ ว่าแอดมินออนไลน์แล้ว

เฉพาะคนที่มีสิทธิ์ **Manage Server** เท่านั้นที่กดปุ่มออนไลน์/ออฟไลน์ได้ คนอื่นกดจะขึ้นแจ้งว่าไม่มีสิทธิ์

⚠️ สถานะออนไลน์/ออฟไลน์เก็บไว้ใน memory เท่านั้น — ถ้า Railway redeploy หรือ container
รีสตาร์ท สถานะจะรีเซ็ตกลับเป็น **ออนไลน์** เสมอ (กด `/setup-status` โพสต์แผงใหม่ หรือกดปุ่มตั้งสถานะ
ใหม่ได้ตามต้องการ ไม่ต้องตั้งคำสั่งซ้ำถ้าแผงเก่ายังอยู่ในห้อง)
